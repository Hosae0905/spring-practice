## 로그인 처리1 - 쿠키, 세션

### 로그인 처리하기 - 쿠키 사용
- 쿼리 파라미터를 계속 유지하면서 보내는 것은 매우 어렵고 번거로운 작업이기 때문에 쿠키를 사용한다. 
- 쿠키에는 영속 쿠키와 세션 쿠키가 있다.
  - 영속 쿠키: 만료 날짜를 입력하면 해당 날짜까지 유지
  - 세션 쿠키: 만료 날짜를 생략하면 브라우저 종료시 까지만 유지
- 쿠키는 보안상 문제가 많다.

### 쿠키와 보안 문제
- 쿠키 값은 임의로 변경할 수 있다.
- 쿠키에 보관된 정보는 훔쳐갈 수 있다.
- 해커가 쿠키를 한 번 훔쳐가면 평생 사용할 수 있다.
- 이러한 보안 문제를 해결하기 위한 대안이 필요하다.
- 쿠키에 중요한 값을 노출하지 않고 사용자 별로 예측 불가능한 임의의 토큰을 노출하고 서버에서 토큰과 사용자 ID를 매핑해서 인식한다. 그리고 서버에서 토큰을 관리한다.
- 토큰은 해켜가 임의의 값을 넣어도 찾을 수 없도록 예상 불가능해야 한다.
- 해커가 토큰을 탈취해도 시간이 지나면 사용할 수 없도록 서버에서 해당 토큰의 만료시간을 짧게 유지한다.
- 해킹이 의심되는 경우 서버에서 해당 토큰을 강제로 제거하면 된다.

### 로그인 처리하기 - 세션 동작 방식
- 쿠키에 중요한 정보를 보관하지 못하니깐 중요한 정보를 모두 서버에 저장하고 클라이언스와 서버는 추정 불가능한 임의의 식별자 값으로 연결해야 한다.
- 서버에 중요한 정보를 보관하고 연결을 유지하는 방법을 세션이라고 한다.
- 클라이언트와 서버는 결국 쿠키로 연결이 되어야 한다.
- 중요한 포인트는 회원과 관련된 정보는 클라이언트에 전달하지 않는다.
- 세션 아이디만 클라이언트에 보낸다.

### 로그인 처리하기 - 세션 직접 만들기
- 세션은 생성, 조회, 만료 세 가지 기능이 필요하다.
- 세션은 특별한 것은 아니고 단지 쿠키를 쓰는데 서버에서 데이터를 유지하는 방법이다.
